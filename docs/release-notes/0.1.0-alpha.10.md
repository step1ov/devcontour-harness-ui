# devcontour-harness-ui 0.1.0-alpha.10

Панель читает ревизию представления 8; договор следует за devcontour-harness
`0.1.0-alpha.68`. Peer прежний: devcontour-harness `>=0.1.0-alpha.55 <0.2.0`;
с прежними версиями всё работает, как раньше (каждое поле ревизии 8
необязательно, документы ревизии 7 показываются, как в alpha.9, плюс
изменения вида ниже). Рекомендуемая пара — devcontour-harness
`0.1.0-alpha.68` и devcontour-harness-ui `0.1.0-alpha.10`.

## Верхнее меню

- Меню с вкладками закреплено сверху и остаётся на месте при прокрутке —
  в светлой и тёмной теме и на ширине 390 px (там бренд и язык — одной
  строкой, вкладки — строкой с прокруткой). Якоря («что проверено») и
  фокус переходов прокручиваются под меню, а не за него: отступ берётся из
  измеренной высоты меню.

## Путь задачи на карточке

- У каждой попытки — своя подсказка: «Попытка 2: код ✓ · проверки ✓ ·
  ревью ✗ — причина · 14:31»; у текущей — «сейчас: ревью, идёт 3 мин»;
  у будущей — «впереди». У отдельных отметок (разбор ведущего, сброс
  попыток, решение человека, итог) — своя: «Разбор ведущего · D1: … ·
  11:40».
- Рядом с линией — короткая подпись «сейчас: ревью (попытка 3)» или шаг,
  который ждёт («сейчас: разбор ведущего — ждёт ведущего»).
- Линия — панель инструментов с одной остановкой Tab: стрелки, Home и End
  переходят между попытками и отметками, фокус и наведение открывают
  подсказку, касание открывает и закрывает её, Escape закрывает. Полный
  список шагов остаётся в деталях работы.

## Карточка задачи

- Главная полоса — путь текущей попытки к приёмке: код → проверки → ревью
  → интеграция → принято. Цифра — готовность из прогноза harness, если он
  называет эту попытку, иначе пройденные этапы пути. После отказа полоса
  начинается заново с подписью «повтор после отказа: <этап>».
- Попытки — значок в углу «попытка 2 из 3»: нейтральный; жёлтый на
  последней попытке; красный, когда попытки израсходованы или работа ждёт
  ведущего. Подсказка значка повторяет строку попыток и сбросы ведущего;
  взятые сбросы («сбросы ведущего: 1 из 2 (+3)») есть и в карточке.
- Строка ревью — из ревью каждой попытки: «Ревью: попытка 1 — отклонено,
  попытка 2 — одобрено» (с числом находок, если harness его передаёт).
  Раунды `harness review-code` ведущего — отдельной строкой
  «Дополнительное ревью кода (ведущий): раунды N из M», только если они
  были. Без пути (старый harness) — прежняя строка.

## Прогноз

- Код принят, а ведущий ещё работает (`release.state: code-accepted`):
  круг «До релиза» не доходит до 100 % — остаток кольца полосатый и
  «дышит» (без анимации при «меньше движения»), под ним «Код принят ·
  осталось немного: ведущий завершает работу (идёт уже N мин)» — время идёт
  по часам зрителя от `time.finishing.since`. 100 % — только после
  `harness release done`. Оценку ведущего, которую он уже превысил
  (`finishing.exceeded` или прошло больше `time.lead.ms`), панель не
  показывает.
- `progress.conditional` — «Цифра — по известному плану: если ведущий
  добавит задачи, она сдвинется назад».
- `progress.growth` — строка harness «план вырос: +<работа> (было 95 % →
  стало 80 %)» и причина записи плана, если есть: откат цифры читается как
  новая работа, а не как сбой.
- «Выпуск по этапам» (`forecast.outline`): полоса из этапов — ширина по
  объёму, заливка по проценту harness, незаведённые этапы штриховкой — и
  строки «продукт — 20 % (заведена часть задач)»; строка плана harness и
  `time.outline` под кругом «Время». Плана нет, а все работы —
  инфраструктура (`progress.infraShare`): «инфраструктура — 30 % (оценка)»
  против «продукт — ещё не спланирован». Плана нет вовсе — подсказка
  harness «плана выпуска нет — прогноз по одному графу…».
- Полоса карточки идёт внутри этапа по `works[].stageProgress` (доли
  попытки на начале и конце этапа, его типичное время): по часам зрителя,
  не дальше конца этапа и не до 100 % до приёмки.

## Ревизия 8 (harness 0.1.0-alpha.68)

- Строка ревью карточки — из `works[].attemptReviews` harness, если поле
  есть: «попытка 1, до доработки — отклонено (3 находки, 1 заметка),
  попытка 2, интеграция — одобрено», «ответ не по протоколу» для
  `invalid`; без поля — из пути задачи.
- `works[].reopened` — строка harness на карточке («переоткрыта ведущим:
  доработка после приёмки (принятый результат <sha> не включён)») и
  «свой предел попыток» / «предел попыток перенесён».
- Вид разбора ведущего (`track.steps[].required`): пустой пунктирный ромб —
  по желанию, залитый — обязательный; плановые шаги — словами harness
  («повтор: harness сам, ведущий может разобрать», «обязательный разбор
  ведущего»), ожидающие и прошедшие — «· обязательный» / «· по желанию».
- «Решения» (`decisions[]`, harness теперь заполняет): виды «разбор
  ведущего», «новый предел попыток», «ответ на вопрос», «ещё раунды ревью»,
  «отмена», «переоткрытие», «доработка оставлена», «повторное согласование
  плана»; неизвестный вид — кодом.
- Остаток раундов ревью (`reviews[].rounds.remaining`, `free`): «раунды 2
  из 6 · раундов ревью плана: осталось 4 · 1 повторное ревью неизменённого
  плана — без траты раунда»; «осталось 0» выделено.
- «Решения»: ещё виды «бюджет поднят» (`budget`, решает человек) и
  «дополнение разбора ведущего» (`diagnosis-addendum`).
- Поля ревизии 8 — в типах представления и в шлюзе совместимости: документ
  с неверным полем ревизии 8 отклоняется шлюзом, а не падает при показе.
  Копии схем harness `0.1.0-alpha.68` и настоящие ответы `harness view` —
  в `tests/contract/harness/`, копии `0.1.0-alpha.67` — в
  `tests/contract/harness-0.1.0-alpha.67/`.

## Для хостов (встраивание)

- `TrackLine` принимает `since`, `now`, `timeZone`; новые экспорты:
  `groupTip`, `stepLabel`, `trackCaption`; модель — `attemptProgress`,
  `attemptReviews`, `leadResets`, `trackNow`, `diagnosisRequired`,
  `ATTEMPT_PHASES`, `attemptReviewResults`, `reopenedOf`,
  `forecastAdditions`, `stageProgressOf`. `Progress` принимает
  `indicatorClassName`.
