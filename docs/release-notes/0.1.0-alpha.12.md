# devcontour-harness-ui 0.1.0-alpha.12 (черновик)

Панель читает ревизию представления 10; договор следует за devcontour-harness
`0.1.0-alpha.70`. Peer прежний: devcontour-harness `>=0.1.0-alpha.55 <0.2.0`;
с прежними версиями всё работает, как раньше (каждое поле ревизии 10
необязательно, документы ревизии 9 показываются, как в alpha.11).
Рекомендуемая пара — devcontour-harness `0.1.0-alpha.70` и
devcontour-harness-ui `0.1.0-alpha.12`.

## Расход

- `costs`: блок «Расход» на «Обзоре» — «Текущий выпуск» (`sinceRelease`:
  вызовы после последнего release done, с его временем; выпуска ещё не было
  — «все вызовы: выпуск ещё не закрывался») и «Вся установка», у каждой
  суммы — число вызовов; ниже — «По ролям» (исполнитель, reviewer, план и
  договор, ведущий, прочее) и «По моделям» с вендором, свёрнуто — «По
  работам и попыткам».
- Нижняя граница (`bound: lower`) — «не меньше $X», у суммы — «без цены: N
  вызовов» (`unpricedCalls`), под итогами — «без цены: N вызовов — суммы не
  меньше показанных»; сумма только из вызовов без цены — «цена неизвестна»,
  а не $0.00. Неизвестная граница читается как нижняя.
- Усечённые списки (`byModelTruncated`, `byWorkTruncated`,
  `byWork[].attemptsTruncated`) — «ещё N моделей», «ещё N работ», «ещё N
  ранних попыток». Панель ничего не складывает: все суммы — harness.

## Карточка работы

- `works[].attemptReviews[].secondPass`: в строке «Ревью» у попытки —
  «второй проход: снято N[, пропущено первым M][, отказ снят]» или «второй
  проход не удался — действует первый»; режим («при отказе» / «всегда»),
  что такое второй проход и «Снятые находки: «…» — основание»
  (`refutedFindings`) — во всплывающей подсказке (по наведению и фокусу,
  читается вместе со строкой).
- `works[].proposals`: «Предложения исполнителя (N)» — вид («продолжение»,
  «разделение»), название (у разделения без названия — слова harness
  «разделение на N части»; без них — id и «частей: N»), попытка, решение
  («ждёт ведущего», «принято», «отклонено»), «цель: …», «почему отдельно: …»
  и «решение — ведущий, время: основание» (`decision`). Пока есть нерешённые
  — «Решает ведущий (harness proposal); принятое войдёт в план через ревью
  плана». Кнопок нет: решение — в CLI.
- `works[].attempts.lastFailure.referenceUrl`: после последнего отказа —
  ссылка «что значит этот отказ» на справочник причин в репозитории harness
  его версии. Без поля (или с адресом не http(s)) — путь `reference` в
  публичном репозитории harness (ветка master). Ссылкой становится только
  `docs/failure-causes.md#<якорь>`.
- В деталях работы — та же ссылка, строка ревью со вторым проходом,
  предложения и «Расход по попыткам» (`works[].cost`: итог, каждая попытка,
  «ещё N ранних попыток»).

## Выпуск

- `forecast.progress.release.docs`: блок «Документация выпуска» под «Ревью
  выпуска» — состояние словами («нет работы документации», «не после всех
  корневых работ», «в работе», «готово»…), режим («обязательно: выпуск
  ждёт» / «совет: выпуск не держит») и строка harness на языке панели. Без
  строки (ранний документ) панель сама называет работы документации и корни
  без неё.

## Договор

- Поля ревизии 10 — в типах представления и в шлюзе совместимости
  (`KNOWN_VIEW_REVISION` = 10): документ с неверным полем ревизии 10
  отклоняется шлюзом, а не падает при показе.
- Копии схем harness `0.1.0-alpha.70` — в `tests/contract/harness/`, копии
  `0.1.0-alpha.69` — в `tests/contract/harness-0.1.0-alpha.69/`; документы
  alpha.69 проходят схемы alpha.70 и шлюз. Настоящие ответы `harness view`
  в `tests/contract/harness/` пока от alpha.69 — их обновит выпущенный CLI
  alpha.70.
