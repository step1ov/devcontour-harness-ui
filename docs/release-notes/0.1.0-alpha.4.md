# devcontour-harness-ui 0.1.0-alpha.4 (не выпущен)

Новый вид панели для человека без технической подготовки: зайти, увидеть
весь объём работ, следить за ним с примерными сроками и видеть проблемы по
ходу простыми словами. Peer прежний: devcontour-harness `>=0.1.0-alpha.55
<0.2.0`. Раздел `scope` (задачи прогона, ещё не переданные в harness)
панель уже читает; harness начнёт его выдавать в одном из следующих
выпусков (предложение P10).

## Вид

- Верхнее меню: **Обзор · Задачи · Решения · Журнал · Настройки**; в
  «Журнале» — «Кто что делал · История · Здоровье».
- Карточки и значки shadcn/ui (Radix + Tailwind CSS 4), тёмная тема — по
  системе или выбором в «Настройках» (хранится в этом браузере).
- Хосту по-прежнему нужен только React: Radix и компоненты собраны в пакет,
  `styles.css` собран заранее, утилиты с префиксом `hui:`, без preflight,
  каждое правило ограничено `.hui`, слои названы `hui-*` — стили не
  протекают на страницу хоста. Глобальны только регистрации
  `@property --tw-*`, такие же, как у самого Tailwind.

## Обзор

- Первая строка — одна фраза о том, что происходит («Сейчас harness
  работает над locale-format (этап «Проверки»).»).
- «Весь объём работ»: сделано / в работе / ждут с полосой, список работ со
  значками и примерный срок диапазоном по фактическому времени («Осталось:
  1,5–2,5 ч на 3 работы — если каждой хватит одной попытки»). Без
  наблюдений срок не показывается как ноль.
- «Проблемы по ходу»: неудачные попытки, остановки, стоящая очередь, сбои,
  бюджет и изменения после приёмки — простыми словами.
- Технический вопрос, на который по политике отвечает ведущий, больше не
  числится «от вас» (F-W).
- Без запущенного контроллера очередь «стоит», а не «идёт», и сказано, кто
  должен запустить её снова (F-X).
- Вопрос показан целиком, без команды `harness input-show` (F-Y); коды
  причин и событий — только в «подробностях» (F-AA).
- Работающая работа не попадает в ожидания (F-J), принятая — в
  остановленные (F-AY).

## Задачи вместо Ревью

- Карточка на каждую работу: что происходит сейчас, попытки (израсходовано /
  осталось), раунды ревью, кто действует дальше, вопросы задачи целиком.
- «Весь процесс» открывает ленту: подготовка → написание кода → проверки →
  ревью → интеграция → приёмка, со временем и итогом каждого этапа; прежние
  попытки — в раскрытии.
- Старый адрес `#/reviews` ведёт на `#/tasks`. Ревью плана и договоров —
  под карточками задач.

## Новая сборка панели

Открытая вкладка замечает, что панель перезапущена с новой сборкой, и
предлагает «Обновить страницу» (F-AF): страница несёт id своей сборки
(`<meta name="hui-build">`), `/api/health` называет сборку, которую
сервер раздаёт сейчас, а страница отдаётся с `cache-control: no-cache`.

## Для встраивания

- Новые экспорты: `Tasks`, `Timeline`, `ThemeChoice`; в модели —
  `overallProgress`, `scopeOf`, `scopeLeft`, `stageLeft`, `attemptAverage`,
  `taskCards`, `timelines`, `splitQuestions`, `formatRough`, `formatRange`.
- `Settings` принимает `theme` и `onThemeChange` (без него блок
  «Оформление» не показывается).
- `Reviews` остаётся в API.
