# devcontour-harness-ui 0.1.0-alpha.1

Первый выпуск для npm. Срез S2 дизайна: все экраны панели только для
чтения, на русском и английском. Нужен devcontour-harness
`0.1.0-alpha.55` или новее в линии `0.1.x` (peer
`>=0.1.0-alpha.55 <0.2.0`).

## Экраны

- **Обзор** (`#/`): фраза «Сейчас… От вас: …», полоса плана, вопросы,
  которые ждут вас (с тем, что изменится для пользователя, и кто может
  ответить), что идёт сейчас, что ждёт решения, что ждёт очереди или
  остановлено — с причиной и тем, кто действует, принятые работы и
  полоса здоровья.
- **Детали работы** (`#/work/<id>`) по документу `harness view --work <id>`:
  этап сейчас и обычная длительность, этапы попытки, «Почему повтор»,
  попытки, «Что проверено» (каждая строка — результат, способ и кем:
  запущено в попытке N, взято прежнее доказательство, reviewer прочитал
  diff и ничего не запускал, не проверялось), расходы, что мешает, вопросы,
  ревью, «Принято: локально и в удалённом репозитории» и дрейф.
- **Ревью** (`#/reviews`): раунды против предела, открытые и решённые
  замечания с тем, кто решил и в каком раунде, эскалации, флаг одного
  вендора.
- **Решения** (`#/decisions`) и **Кто что делал** (`#/activity`, фильтр по
  работе и исполнителю). harness `0.1.0-alpha.55` этих полей ещё не
  выдаёт — экраны так и пишут: «нет данных в этой версии harness».
- **Настройки** (`#/settings`): кто пишет и кто проверяет, действующий
  reviewer кода для каждой роли и откуда он взят, пороги вопросов
  обычными словами, строка «Технические вопросы решает ведущий: да/нет»,
  пределы, бюджеты, таймауты; «по умолчанию» — только у путей из
  `settings.defaulted`.
- **История** (`#/history`): нагрузка, начатые и неудачные попытки в час,
  проверки, накопленные расходы против бюджета. Встроенный SVG без
  библиотек; у каждого графика текстовая сводка и таблица данных для
  экранного диктора; кривая расходов начинается с расходов до окна и
  пунктирна, когда это нижняя граница.
- **Здоровье** (`#/health`): контроллер, зависшие и тихие попытки, сбои
  окружения, бюджеты, дрейф («не проверено» никогда не ноль),
  предупреждения harness с кодом, версии.

## Правила слов

- «Проверено» не пишется без способа и того, кто проверял; «принято» — без
  того, где (локально; в удалённом репозитории — да, нет или неизвестно);
  «ждёт» и «остановлено» — без причины и того, кто действует. Тест по
  разметке проверяет это для каждой строки с `data-status`.
- Неизвестное показывается словами «неизвестно», «не проверено» или «нет
  сведений», а не нулём или «в порядке».
- У терминов есть раскрывающееся «что это значит» из глоссария.

## Язык

- Все подписи — из одного словаря; тест проверяет, что у русского и
  английского есть каждый ключ.
- `--lang ru|en`, по умолчанию из системной локали; `?lang=` на странице
  сильнее флага; язык передаётся harness (`harness view --lang`).
  Компоненты по умолчанию русские (`lang="ru"`).
- Демонстрация (`--demo`) отдаёт тексты harness по-русски для `?lang=ru`.

## Сервер и CLI

- Новый маршрут `GET /api/work/<id>` (и `GET /api/view?work=<id>`): живой
  маршрут запускает `harness view --work=<id>` с тем же языком, таймаутом и
  отказами, что `/api/view`. Id проверяется по алфавиту id графа, иначе 404.
  У файла `--view` деталей нет (503).
- `checkWorkDetail` проверяет документ деталей так же, как `checkView`
  проверяет обзор; оба шлюза теперь проверяют каждое поле, которое
  отображают экраны.
- `httpViewSource(...).loadWork(id)` и `staticViewSource(view, works)`.
- Живой маршрут запускает не больше 4 процессов harness одновременно и
  держит до 16 запросов в очереди; лишний запрос сразу получает 503.
- `/api/health` сообщает язык CLI: без `?lang=` страница берёт язык
  `--lang` (или системной локали), а не браузера.
- Временный отказ `VIEW_UNAVAILABLE` после удачного документа оставляет
  последний документ на экране с баннером «Связь потеряна».

## Доступность

- Навигация по hash-адресам с клавиатуры, видимый фокус, ссылка «К
  содержимому», фокус переходит на экран при смене раздела.
- При 390 px нет горизонтальной прокрутки; таблицы складываются в
  карточки.
- axe без серьёзных нарушений на каждом экране в светлой и тёмной теме;
  `prefers-reduced-motion` отключает анимации.
- Live-регион объявляет только число вопросов, которые ждут ответа.

## Проверки

Playwright против `--demo` при 1280 и 390 px (нужен локально установленный
Chromium Playwright).
