# devcontour-harness-ui 0.1.0-alpha.5 (не выпущен)

Прогноз выпуска на главной: два больших круга «До релиза» и «Время» по
данным harness, а не по расчёту панели. Панель показывает новые факты
harness 0.1.0-alpha.60 вместо своих догадок: кто двигает очередь, в каком
порядке снимать блокировки, засчитана ли попытка. Вопросы владельцу из
трекера задач, весь срез прогона и обновления — на своих местах. Peer
прежний: devcontour-harness `>=0.1.0-alpha.55 <0.2.0`; рекомендуемая пара —
devcontour-harness `0.1.0-alpha.60`.

## Прогноз выпуска (ревизия 4, поле `forecast`)

- Наверху «Обзора» — два круговых индикатора:
  - «До релиза» — процент готовности всего объёма прогона («~23 %») и
    строка harness «готово ~23 %, осталось задач: 5 из 6, в работе: 1»;
  - «Время» — «прошло 2 ч 50 мин · осталось ~1,5–3 ч», диапазон по
    наблюдённым попыткам, с основанием (сколько попыток, попыток на
    задачу).
- Ожидание людей и ведущего — отдельной строкой и в прогноз не входит.
- Мало наблюдений — круг «Время» в состоянии «неизвестно» (пунктир и «?»)
  с причиной, а не ноль. Ничего не осталось — полный круг.
- Допущения harness — под «что это значит», с теми же строками, что
  печатает `harness status --human`.
- Каждый круг — `role="progressbar"` с именем, значениями и текстом; обе
  темы; при 1280 px круги рядом, при 390 px один под другим.
- С harness до alpha.60 кругов нет: карточка «Весь объём работ» говорит
  почему и показывает прежние полосу и оценку панели. С прогнозом оценка
  панели («одна попытка в среднем …») больше не показывается.

## Остальные поля ревизии 4 (harness 0.1.0-alpha.60)

- **Очередь.** «Очередь стоит» решает harness (`progress.queue.runner`);
  рядом его строка и кто запускает («запускает: ведущий»). Прежняя догадка
  по контроллеру — только для старых harness.
- **Порядок снятия блокировок** (`blockers[].step`): «Сначала ведущий: ….
  Затем — вы.» в порядке harness, не по списку кодов панели.
- **Засчитана ли попытка** (`lastFailure.kind`, `counted`): остановка,
  которая ждёт ведущего, узнаётся по фактам harness, без разбора фразы;
  строки последнего сбоя говорят «попытка засчитана / не засчитана».
  Для harness alpha.59 остаётся прежнее распознавание.
- **Этап «Ревью плана»** (`plan-review`): ход harness, а не ожидание.
- **Вопрос целиком:** варианты ответа с пометкой «рекомендуется»,
  обоснование исполнителя и где применённый ответ («ответ передан попытке
  2»).
- **Вопросы владельцу из трекера** (`sourceQuestions[]`) — в «Нужно от
  вас»: вопрос, варианты, рекомендация, временный ответ, задачи и ссылка
  на документ (только `http(s)`). Отвечают в трекере.
- **Весь срез прогона** (`scope`): задачи, ещё не переданные в harness, — в
  «Обзоре» и «Задачах», по ключу и заголовку.
- **Совместимость с трекером** (`health.sources[]`) — в «Здоровье».
- **Обновления** (`updates`): полоса «Доступна … — что нового · как
  обновить» с командой harness; режим обновлений — в «Настройках», только
  для чтения. Панель сама ничего не ставит и в сеть не ходит.
- `KNOWN_VIEW_REVISION = 4`; ревизии 0–3 (harness alpha.55–.59) рисуются
  по-прежнему.

## Публикация

Перед публикацией `prepack` запускает `scripts/check-deps.mjs`: он сверяет
установленные `node_modules` с `package-lock.json`, а корень lock-файла — с
`package.json`. Если установлена другая версия, пакет не установлен или
lock-файл отстал от `package.json`, публикация останавливается до сборки с
сообщением «Зависимости не совпадают с package-lock.json — выполните npm ci
и повторите npm publish» (и английским двойником) и списком расхождений.
Публикация владельцем:

```sh
git pull && npm ci && npm publish --tag alpha
```
